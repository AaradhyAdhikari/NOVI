# Novi — project guide for Claude

Novi is a voice-first personal AI companion that runs on the user's Windows laptop (vision: `NOVI CONTEXT.txt`, user-facing docs: `README.md`).

**Where Novi lives (moved 2026-10-28, user's choice): `C:\dev\NOVI`**: plain ASCII, outside OneDrive, so every tool and terminal works. The old `OneDrive\ドキュメント\NOVI CONTEXT` folder is a leftover copy; never work there. The user's projects live next to it in `C:\dev\<Project>` (Portfolio, Tip calculator, SIH_proto_5th; `.env` `NOVI_PROJECTS_DIR=C:\dev`, so new projects go there too) and Novi Memory is `C:\dev\Novi Memory` (`NOVI_MEMORY_DIR`). MediKiosk, FLEXR, TraceBites etc. are claude.ai-only (no folder).

## Hard rules
- **Claude only for coding (user's decision 2026-10-08).** Novi's brain (chat, tools) runs on free Groq/Gemini keys. Coding tasks default to Claude Code on the user's logged-in Pro plan when it's installed (`NOVI_CODER=free` turns that off); the brain picks Novi Coder (free) for small edits and Claude for bigger work, and the user's named choice always wins. Never run the real `claude` CLI in tests; use `tests/fixtures/fake-claude.mjs`.
- **Keep Claude usage low while building:** work inline (no subagents), read only the files you need, keep tool output short (redirect long logs to a file and read the tail).
- **Every feature is a plugin** in `plugins/<id>/` written in OpenClaw's plugin shape (see `docs/PLUGINS.md`). Novi will later move onto OpenClaw via one adapter; don't put feature logic in `server/` core unless it's a shared service exposed through `api.runtime`.
- **Every project lives in Claude too (user, 2026-10-18, for all upcoming projects):** each project Novi works on is a folder Claude Code works in (shows in Claude Code's project list) AND a claude.ai Project (name, description, instructions naming the folder + latest brief) — `plugins/claude-link` makes it automatically for each new project and for any coding task on a project without one; Claude Code's earlier folders AND every claude.ai Project (with its link, folder or not) are remembered as Novi's projects. In Novi Memory each project is one dot ("X project": folder, claude.ai link) with everything about it hanging off it ("X brief", any note named "X …", its README, logo and pictures).
- Anything that sends, posts, changes or deletes needs an approval (`before_tool_call` → `requireApproval` with `severity: 'warning'`; `'critical'` = screen-only). Private data results set `details.sensitive = true` (keeps the turn on Groq).
- TDD: write the test, watch it fail, implement, watch it pass, run the full suite. Work directly on `main`.
- **The user makes the commits** (so they count on their GitHub): do NOT `git commit` or `git push`. When a piece of work is done and the suite is green, tell the user to double-click **`Commit and Push.cmd`** (asks for a message, commits everything except `NOVI CONTEXT.txt`/`.env`/`data/` under their name, pushes the current branch) and suggest a commit message.
- Never print or commit secrets (`.env`, `data/`). Check `.env` only for names/shapes.
- **Cloud sessions: every commit is authored as the user** — `Aaradhy Adhikari <adhikari.aaradhy26@gmail.com>` (`.claude/settings.json` SessionStart hook sets it and turns off the container's commit signing, whose key isn't on the user's GitHub — signed commits showed "Unverified"; check `git config user.name` before committing). No `Co-Authored-By: Claude` line (user, 2026-10-17: contributions must show their name). The user merges PRs with merge commits, which keep these authors.
